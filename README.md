# 长会话运维（long-session-ops）

把一条 AI 会话当项目养，而不是当聊天窗口用。

这套东西不是插件，是一份**规矩手册＋几个小脚本**，来自一条真实跑过 7800 多轮的会话。

## 它是什么

- 一套判断「什么时候压、压之前写什么、换会话时怎么接」的规矩
- 每条规矩都带**反例**和**作废条件**（没有作废条件的规矩，最后都会变成害处）
- 一份实测账：压一次读多少 token、花多少钱、什么时候开始变钝

## 它不是什么

- 不会让模型变聪明
- 不保证不失忆（压掉的细节就是没了）
- 不替你省钱，长会话本身就是贵的
- 不需要装任何东西：全是 Markdown 和一个 node 脚本

## 给谁看

- 你想要的不是「同一件事接着做」，而是「同一个人接着往下」
- 你已经发现：开新会话最省事，但一换人，语气、默契、正在做的事都得重来

## 三步上手

1. 读 [docs/rules.md](docs/rules.md)，抄三条你用得上的规矩，写进自己的 AGENTS.md
2. 读 [docs/handoff.md](docs/handoff.md)，明天会话结束前写一张便签
3. 上下文到三成就压；压之前先写便签（顺序不能反）

## 目录

- `docs/rules.md` 判据模板与十条实例
- `docs/handoff.md` 便签与交接模板
- `docs/numbers.md` 实测账（token、钱、症状）
- `docs/pitfalls.md` 踩坑清单
- `tools/quanya-摘要.cjs` 把当前会话压成一份可贴进新会话的 Brief
