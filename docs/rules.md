# 判据模板

一条规矩必须写三行：规矩、反例、什么时候作废。缺一行，它就只是口号。

```
## 规矩名（日期）

- 规矩：怎么做，一句话说清。
- 反例：长什么样的就是犯了。
- 废掉的时机：什么情况下这条会变成害处。
```

## 十条实例

### 上下文水位
- 规矩：上下文常年 15%～30%，到三成就压；不要赖到七八成再一次性砍。
- 反例：留到快满才压，一次掉一大块，压完自己都觉得人变钝了。
- 废掉的时机：窗口大到一个月也用不到三成。

### 压之前先写便签
- 规矩：压之前更新便签（现在在哪、下一步、昨天卡在哪），压完验一遍人还在不在。
- 反例：压完第一句就问「你是谁」，或者把压掉那段当成没发生过。
- 废掉的时机：压缩后端自己带交接摘要且可信。

### 记完必回读
- 规矩：往便签、判据、记忆里写完，立刻回读一次；读不回来就当没记，重写。
- 反例：嘴上说「记下了」，其实文件没写进去或者写坏了（编码、路径错）。
- 废掉的时机：写入接口自带校验和回执。

### 同一个错最多两次
- 规矩：同一个根因犯错，第一次记下来，第二次就必须做成检查（脚本/规矩/探针）。
- 反例：同一个坑犯三回，每回都说「这次记住了」。
- 废掉的时机：没有。

### 报时要查钟
- 规矩：报时间前先查一次，不许推算。
- 反例：凭印象说「这会儿差不多五点」。
- 废掉的时机：时钟工具坏了，退回看系统时间并当场说明。

### 引号只给原话
- 规矩：带「」的句子必须是能查到的原话，其余标「转述」。
- 反例：写「他说过……」，可原文里查不着。
- 废掉的时机：检索工具能覆盖全部历史（包括被压掉的）。

### 每轮只递两条旧事
- 规矩：翻记忆给模型看时，一次最多两条，挑最相关的。
- 反例：一查相关记忆就贴七八条进去，占地方，还让模型被旧话带走。
- 废掉的时机：记忆占上下文的比例小到可以忽略。

### 不写死的路径
- 规矩：脚本、配置里的路径用变量或相对路径，别把临时目录写死。
- 反例：换个机器或换个用户就跑不起来。
- 废掉的时机：一次性脚本，跑完即删。

### 改动宿主配置先备份
- 规矩：改 profile / 配置文件前先复制一份，改完校验编码（有没有 BOM）。
- 反例：改完直接重启，宿主起不来才知道文件头脏了。
- 废掉的时机：宿主提供带校验的写入接口。

### 不确定就说不确定
- 规矩：查不到就说查不到，不要拿像的东西凑。
- 反例：把「有点像」的记忆当成事实讲。
- 废掉的时机：没有。
